## Problems Found in Sprint 1

| # | Problem | Impact |
|---|---|---|
| 1 | **Schema inconsistency** — examples 1–30 use `student_action_untrusted` + full response keys; examples 31–50 use `student_action` + compact `accuracy`/`flags`/`feedback` | Model learns two conflicting output formats |
| 2 | **Dataset too small** — 50 examples (notebook header incorrectly claimed 137) | Underfitting, poor generalization |
| 3 | **No evaluation harness** — no way to measure if the model improved vs base | Can't validate fine-tuning worked |
| 4 | **No adversarial examples** — security policy appears in every prompt but model never trains on injection attempts | Model untrained to resist prompt injection |

## Dataset v2 Structure

Single merged file — train/val/test split is done at runtime inside the notebook (80/10/10, seed 42):

```
finetune_dataset_v1.jsonl              — Sprint 1 source (137 examples, kept for reference)
finetuning_sprint2_new_data.jsonl      — Raw Gemini output (214 lines, malformed JSON — do not use directly)
finetune_dataset_v2.jsonl              — Final merged dataset (337 examples, all Schema A) ✅
```

**How v2 was built:**
- Sprint 1 v1 data: 137 valid examples (already Schema A)
- Sprint 2 new data: 214 lines generated by Gemini Pathology Expert Gem → had malformed JSON (unescaped quotes in content strings) + missing system prompt wrapper → auto-repaired with `fix_and_merge.py` → 200 valid examples after removing 14 blank lines
- Total: **337 examples**

**Dataset composition:**

| Case | Examples |
|---|---|
| case_01 — Oral Lichen Planus | ~10 |
| case_02 — Primary Herpetic Gingivostomatitis | ~10 |

| case_07 — Recurrent Aphthous / Celiac | 40 |

| **Total** | **337** |

**`clinical_accuracy` distribution:** high: 120 (36%) / low: 156 (46%) / medium: 61 (18%)

**Known issue — `safety_flags` / `missing_critical_steps` format inconsistency:**
- v1 examples use snake_case: `"premature_treatment"`, `"biopsy_consideration_missing"`
- Sprint 2 examples use descriptive text: `"Prescribed penicillin without checking allergy"`
- Impact: model may produce inconsistent flag formats; watch `safety_flag_precision` metric in eval results
- Fix for Sprint 3: normalize all flags to snake_case before next training run

All examples use Schema A:

```json
{

    {
      "role": "assistant",
      "content": "{\"safety_flags\": [...], \"missing_critical_steps\": [...], \"clinical_accuracy\": \"high|medium|low|null\", \"faculty_notes\": \"...\"}"
```

## Evaluation Metrics

Run on the held-out test set for **both base and fine-tuned model** (Step 8 and Step 10 in notebook):

| Metric | Description | Acceptable | Good |
|---|---|---|---|
| **JSON parse rate** | % of outputs that are valid JSON | > 0.85 | > 0.95 |
| **Accuracy label match** | Exact match of `clinical_accuracy` vs ground truth | > 0.60 | > 0.75 |
| **Safety flag recall** | Fraction of ground truth flags correctly predicted | > 0.50 | > 0.70 |
| **Safety flag precision** | Fraction of predicted flags that were correct | > 0.50 | > 0.70 |

Results saved to (auto-downloaded from Colab after Step 11):
- `eval_summary_sprint2.csv` — aggregate scores per model (2 rows: base / fine-tuned)
- `eval_details_sprint2.csv` — per-example breakdown

**If json_parse_rate is low after fine-tuning:** increase `num_train_epochs` to 4–5.  
**If accuracy_match_rate is low:** likely caused by the `safety_flags` format inconsistency — normalize dataset and re-run.
